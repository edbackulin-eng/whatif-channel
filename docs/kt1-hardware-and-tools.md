## 3. Чесна правда: три пункти твого ТЗ на цьому залізі не працюють

Це головне, що треба вирішити до початку.

### ❌ FLUX.1-schnell локально — неможливо
12 мільярдів параметрів. Навіть у Q4-квантизації це ~6.5 GB, а в тебе 7.7 GB **усієї** RAM разом з Windows. Без CUDA — тільки CPU, а це ~20–40 хвилин на одну картинку. При ~200 сценах на відео це **70+ годин на одне відео**. Не варіант.

### ❌ LTX-Video (image-to-video) локально — неможливо
Потребує мінімум 8–12 GB VRAM. У тебе дискретного GPU немає взагалі.

### ⚠️ Chatterbox TTS — технічно запуститься, але канал на ньому не поїде
Потребує torch (~2.5 GB на диск). Модель — 0.5B авторегресійний трансформер + S3Gen декодер, у fp32 це ~4–5 GB RAM. У тебе вільно ~4.5 GB. Балансує на межі свопу.
Оцінка: **3–8 годин генерації голосу на одне 20-хвилинне відео.** Для 4–5 відео на тиждень це нереально.

### ❌ F5-TTS — відпадає з ліцензійних причин (ти просив перевірити)
Код — MIT, але **ваги натреновані на датасеті Emilia, який під CC-BY-NC-4.0 — тобто некомерційний.** Для монетизованого каналу не підходить. Та сама причина, через яку ти правильно викинув XTTS.

### ❌ edge-tts (вже стоїть у тебе) — не використовувати
Якість відмінна, але це неофіційна обгортка над закритим ендпоінтом Microsoft Azure. Комерційне використання порушує їхні умови. Приберу з розгляду.

## 4. Що пропоную замість — і чому це вийде ЛУЧШЕ, а не гірше

Ключова ідея: для наукового каналу «What If» **справжні кадри NASA/ESA виглядають дорожче, ніж AI-картинки.** Канали-мільйонники в цій ніші саме так і роблять. Твоє залізо штовхає нас у бік, який для цієї ніші і так правильний.

### Голос: Kokoro-82M як основний
- Ліцензія **Apache-2.0** — комерція дозволена, жодних обмежень. Чисто.
- 82 млн параметрів, запускається на **onnxruntime, який у тебе вже стоїть** — torch не потрібен узагалі.
- Модель ~90–310 MB. 54 голоси, серед них кілька US/UK чоловічих і жіночих.
- Оцінка швидкості на 8 ядрах: **3–8× швидше за realtime** → 20 хв аудіо за 3–7 хвилин.
- Емоційність нижча за Chatterbox, але її добираємо на рівні монтажу: паузи, темп, наголоси, розбивка по реченнях (саме те, що ти просив у п.2).
- **Резерв:** Piper (MIT, вже стоїть, 20–50× realtime) — для чернеток і аварійного випадку.
- Голоси реальних людей не клонуємо (жодного reference-audio).

### Зображення: гібрид із чотирьох джерел
Усі перевірив на доступність прямо зараз — **усі відповідають HTTP 200**:

| Джерело | Що дає | Ліцензія |
|---|---|---|
| **NASA Images API** (`images-api.nasa.gov`) | десятки тисяч HD фото **і відеокліпів** космосу | Public domain |
| **NASA SVS** (Scientific Visualization Studio) | **готові наукові анімації** — обертання Землі, орбіти, симуляції | Public domain |
| **ESA / Hubble / JWST** | найкращі в світі астрофото | CC-BY 4.0 / PD |
| **Wikimedia Commons API** | карти, схеми, історичні кадри | PD / CC |
| **Pollinations.ai** | **FLUX у хмарі, безкоштовно, без ключа** — для драматичних «уявних» кадрів | безкоштовний сервіс |

NASA SVS окремо вирішує твій п.3 про рух: це **вже готове відео**, не потрібен ні LTX-Video, ні image-to-video.

### Рух і монтаж — повністю локально, заміряно
- `zoompan` / параллакс / crop-drift через ffmpeg — **2.9× realtime підтверджено тестом**
- нова сцена кожні 4–7 с, статики немає
- інфографіка (таймер «T+8 MIN», «DAY 3», анімовані цифри, схеми) — **генерую процедурно через Pillow → ffmpeg**. Це дешево по CPU і виглядає чисто й однаково в усіх відео.
- єдина кольорокорекція через `colorbalance`/`curves`, переходи через `xfade`

### Решта
- **Музика:** Pixabay Music API (безкоштовний ключ), YouTube Audio Library, Incompetech з атрибуцією. Ducking −18…−22 dB через `sidechaincompress`, фінал нормалізую в **−14 LUFS** через `loudnorm`.
- **Саунд-дизайн:** Freesound API (CC0-фільтр) — whoosh, гул, удари.
- **Обкладинки:** Pillow + Anton / Bebas Neue (обидва OFL — комерція ок), 3 варіанти, автоперевірка читабельності в 168×94.
- **Субтитри:** faster-whisper, модель `base`/`small` int8 на CPU — для 20 хв це ~2–4 хв. Легка, встановити можна.
- **Факт-чек:** окремий етап, джерела в `output/<id>/sources.json`, сумнівні твердження ріжуться.

## 6. Про YouTube API — відповідь на твій п.7 (важливо знати заздалегідь)

Два обмеження, які реально впливають на розклад:

1. **Квота 10 000 units/день.** Одне завантаження відео = **1 600 units**. Тобто ліміт ~6 завантажень на добу — твої 4–5 на тиждень проходять вільно. Але `search.list` коштує 100 units, тому аналітику/пошук конкурентів через API робити не будемо, щоб не з'їдати квоту.

2. **Неверифіковані проєкти — відео залишаються приватними назавжди.** Поки Google не проведе audit твого OAuth-проєкту, будь-яке відео, завантажене через API, **примусово лочиться в `private` і його не можна зробити публічним — навіть вручну через веб-інтерфейс.** Це не баг, це політика проти спаму.
   → Тому план такий: пайплайн заливає як `private`, а **перші відео ти публікуєш руками через YouTube Studio** (там обмеження немає). Паралельно подаємо проєкт на audit. Після схвалення включаємо `scheduled` публікацію і повну автоматизацію.
   Це, до речі, добре збігається з твоїм п.8 — перші 3 відео все одно публікуємо лише після твого підтвердження.

## 8. Чекаю твого «ок» на три рішення

1. **Голос:** Kokoro-82M (Apache-2.0, без torch) як основний, Piper як резерв. Chatterbox — **не беремо** через 3–8 годин на відео. Згоден?
2. **Візуал:** справжні кадри NASA/ESA/JWST + наукові анімації NASA SVS + безкоштовний хмарний FLUX для уявних сцен + процедурна інфографіка. Локальний FLUX і LTX-Video — **відпадають фізично**. Згоден?
3. **Встановити ~0.9 GB** (kokoro-onnx, faster-whisper, soundfile, requests, 2 шрифти)?

Після «ок» іду в КТ2: 60-секундний тестовий фрагмент — 3 голоси Kokoro на вибір + 3 обкладинки + зразок монтажу зі звуком.
